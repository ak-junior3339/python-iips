Q- Why does d2 = d not create a copy, and what is the difference between d.copy() and copy.deepcopy(d) for a nested dictionary? Which one would you use for the student database and why?
A- Reference assignment (d2 = d) merely binds a new variable name to the exact same dictionary object in memory rather than creating a copy, meaning changes made through d2 directly affect d. While .copy() creates a shallow copy where top-level keys are duplicated, any nested mutable objects like the inner marks dictionary are still shared references. For the student database, a deep copy (copy.deepcopy()) is necessary because each student record contains a nested dictionary of marks; a shallow copy would leave the inner dictionary linked, causing unintended side effects if one record's grades are modified.

Q- When would you use d[key], d.get(key) and d.get(key, default)? Give one case from your programs where each is the right choice.
A- Dictionary keys must be hashable because Python dictionaries rely on hash tables to achieve efficient O(1) lookups by converting keys into fixed integer indices. If a key's value could change, its hash would change, breaking its memory location. Among the given options, the list [1, 2] and set {1, 2} are mutable and unhashable, making them invalid keys. Conversely, the tuple (1, 2) (assuming its elements are hashable) and the string "12" are immutable and hashable, making them valid dictionary keys.Using d[key] directly accesses a value but raises a KeyError if the key is missing, making it ideal when you have already validated the key's existence, such as retrieving a validated student roll number in showRecords(). In contrast, d.get(key) returns None instead of crashing when a key is absent, which is useful for optional configurations. Finally, d.get(key, default) returns a custom fallback value if the key is missing, making it the right choice for initializing and incrementing counts in frequency counters like word_counts.get(word, 0) + 1.

Q- Explain the difference between .update() and assigning d[key] = value in a loop. When is .update() cleaner?
A- Direct assignment (d[key] = value) adds or modifies a single key-value pair per statement, whereas .update() merges an entire iterable of key-value pairs or another dictionary into the target dictionary in a single operation. Using .update() is cleaner and more efficient when you need to bulk-import records or merge multiple updates simultaneously, avoiding repetitive individual assignment statements.

Q- In Q2, why is "create a new dictionary with a comprehension" safer than modifying salaries in place? When would in-place modification be the better choice?
A- Creating a new dictionary via a comprehension is safer because it preserves data immutability and integrity, ensuring that original records remain unchanged for auditing and historical analysis. In-place modification would be the better choice only when working with massive datasets where memory optimization is critical, or when the application's core requirement dictates a direct transactional update to the live database.


Q- Why does deleting keys while looping over a dictionary fail, and what are two safe ways to do it?
A- Deleting keys while iterating directly over a dictionary raises a RuntimeError because structural modifications invalidate the internal iterator's memory tracking. To do this safely, you can iterate over a static copy or list of the dictionary's keys using list(d.keys()) before performing deletions, or you can use a dictionary comprehension to filter out unwanted items into a brand-new dictionary.
